# About the data in this repository

All data in this repository is synthetic. It was written for this training scenario and describes a fictitious company, Zava, Inc. Nothing in it is a record of a real company, store, product, person, device or event.

## What the data is

| Data | Files | What it holds | How it was made |
|---|---|---|---|
| Stores and cases | `data/seed.json` | Five stores, their refrigerated cases, setpoints and case notes | Generated with AI from a specification, reviewed by hand |
| People and owners | `data/roster.json` | Roles, night cover, pager rules and system owners. Roles only, no names | Generated with AI from a specification, reviewed by hand |
| Tracker tickets | `data/issues.json` | In-character tickets from the store systems tracker | Generated with AI from a specification, reviewed by hand |
| Night runbook | `data/runbook.md` | An out-of-date night operations runbook, used in the exercises | Generated with AI from a specification, reviewed by hand |
| Customer-impact inputs | `data/forecast.json` | Invented shopper counts and buy rates for the simulated prediction | Generated with AI from a specification, reviewed by hand |
| Nights | `nights/*.json` | Four scripted nights: what happens and when | Generated with AI from a specification, reviewed by hand |
| Readings, alarms and the event feed | Generated when the application runs | Temperatures, alarms, pages, the event feed and the customer-impact prediction | Generated by the simulator code in `zava_cold_chain/` |

## How it was made

* **Unseeded.** No existing dataset, records, documents, transcripts or customer content were used as input. Every value, ticket and note was invented for this scenario.
* **Generated from a specification.** The data files were generated with the GPT-6.1-sol model in GitHub Copilot in Visual Studio Code, from a written specification of the fields, identifiers and situations the exercises need. The specification contained no existing data. The maintainers reviewed every file.
* **Generated by code at run time.** Temperatures and alarms come from a simple model of how a case warms and cools, plus Python's pseudo-random number generator started from a fixed value (`random.Random(7)`), so every replay of a night is the same. No AI model runs while you use the application. The store assistant uses simple rules in place of a language model.

## Intended use

The data exists so that people can practise the HVE workshop steps on a small, safe sample application: read the code, find the gaps, plan a change and make it. It is not intended for any other use.

## What it does not contain

* **Personal data.** There are no names, contact details or personal identifiers. People appear only as roles and teams, such as "regional night cover" or "Store operations".
* **Customer data.** There is no data from any customer, shopper or organization.
* **Confidential information.** There is no confidential information from Microsoft or any third party.
* **Real organizations, places or equipment.** Zava is listed in Microsoft's approved fictitious company names. Store names, case IDs, firmware versions and ticket numbers are invented.
* **Real events.** The nights are made-up teaching situations, not accounts of real incidents.

## Checks performed

* The maintainers reviewed every data file by hand.
* Every string in the data and nights was scanned for email addresses, phone numbers, web addresses, personal names, real company and brand names, and real places.
* Each data file carries a note that it is synthetic, and a test in `tests/test_repo_hygiene.py` keeps those notes in place.

## Limits

* The data is not realistic. Temperatures, warming and cooling rates, defrost behaviour, alarm limits and timings are invented for teaching. They are not calibrated against real equipment.
* Shopper numbers and the customer-impact prediction are invented. They are not a forecast of anything.
* Don't use this data for food-safety, HACCP or regulatory decisions, to benchmark real systems, or to train or evaluate models.
